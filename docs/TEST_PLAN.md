# Verification plan

This plan verifies Server Guard against the design contract in `docs/` and gates the phase
exits in [TODO.md](../TODO.md). Where a gate restates the policy contract, [POLICY.md](POLICY.md)
is canonical.

## Test layers

Each layer names what it verifies, the components it targets, and the phase exits it gates. A
phase closes only when every layer gating it passes. Layers 1-4 run in CI on every change;
layers 5-7 run on the operator's licensed server per release candidate and during Phase 10
calibration.

| # | Layer | Verifies | Target components | Gates phase exits |
|---|---|---|---|---|
| 1 | Unit | Ledgers, bounded windows, score decay, token buckets, pseudonymization, redaction, hash chaining, config validation, response policy | Ledgers, `InvariantEngine`, `BehaviorEngine`, `EvidenceStore`, `ResponseCoordinator`, config | 2, 3, 7, 9 |
| 2 | Property | Item conservation, transaction idempotency, score monotonicity, bounded memory, time rollback, numeric overflow, NaN/infinity, event reordering | Ledgers, evidence chain, token buckets | 3, 4, 5, 6, 7 |
| 3 | Metadata contract | Exact type, full method signature, parameter role, return type, metadata token against the installed assembly; fail-open resolution and runtime fault guard | `HookRegistry`, build fingerprint, hook manifest | 1, 2 |
| 4 | Offline replay | Deterministic replay of versioned synthetic traces; expected findings per trace | Detector set, evidence pipeline | 5, 6, 7, 8 |
| 5 | Integration | Stock clients and `7dtd-loadgen` on a live server; observe first, then one corrective invariant per run; co-patching | Full pipeline | 4, 5, 6, 7, 8, 10 |
| 6 | Performance A/B | Overhead vs baseline with `7dtd-apm` under identical scenarios | Hot path, evidence writer, queues | 2, 10 |
| 7 | Human soak and review | Labeled long-run findings; label feedback into the regression corpus | Evidence, review tooling | 5, 9, 10 |

### 1. Unit tests

Pure tests with an injected clock and seeded RNG; no wall clock and no real filesystem beyond
a temp directory. Cover every branch of: movement, combat, inventory, and world ledgers;
bounded windows; score decay; per-connection and global token buckets across cost classes;
HMAC pseudonymization (key rotation, identity map); redaction and tombstones; hash chaining
(segment close, rotation); strict versioned config (unknown-key and invalid-range rejection);
and the response policy (cooldowns, gates, dry-run diff).

Exit: all modules covered; the layer is green in CI per change.

### 2. Property tests

Property-based tests with shrinking, seeded and CI-fixed. Invariants: item conservation (sum
of authorized deltas equals the observed delta), transaction idempotency (replay is a no-op),
score monotonicity (score never decreases from the same evidence), bounded memory (per-player
state is bounded at any packet rate), time rollback (a clock step-back cannot create credit),
numeric overflow and NaN/infinity (no ledger state may become NaN or overflow), and event
reordering (results do not depend on delivery order). Each property run is time-bounded
(e.g. 30 s) and every failure ships with a shrunk minimal counterexample.

Exit: all invariants hold across randomized sessions; shrink reports are committed on failure.

### 3. Metadata contract tests

Run against the locally installed pinned build (V3.1.0 b14). Resolve every type, full method
signature, parameter role, return type, and metadata token used by any hook. A mismatch
disables that detector and is reported; startup stays fail-open. Also verify the runtime
fault guard: a hook fixture that throws increments the per-hook fault counter and self-disables
past the small limit without breaking the connection's package loop. The hook manifest and
build fingerprint must be byte-identical on reload.

Exit: full resolution on the pinned build; the mismatch and runtime-fault fixtures fail open.

### 4. Offline replay tests

Versioned synthetic traces recorded as JSONL (schema version, tick, monotonic clock, payload),
generated by `7dtd-loadgen` and augmented by hand-mutated traces. Each trace is replayed with
the hook-manifest hash of the build that recorded it; a fingerprint or schema mismatch skips
the trace and reports it instead of replaying blindly.

Per-detector fixture catalog: every detector in the [registry](DETECTORS.md) ships at least
one normal and one violation trace, and the contextual families cover the exclusions that
detector's signals require. The exact fixture set per detector is declared in
`tools/detector_spec.yaml` and rendered as the coverage matrix in DETECTORS.md; the matrix
is the gate checklist for this layer:

| Family | Coverage |
|---|---|
| normal | legal play for the detector; must produce no finding |
| violation | one rule break; must produce a finding with the expected detector ID, severity, and mode |
| latency / stall | high ping, jitter bursts, server frame debt, chunk starvation; soft scoring must be suppressed with `suppressedReason` while the raw finding is preserved |
| reconnect / duplicate session | grace windows and session epochs |
| teleport / vehicle / death | discontinuity reset rules; stock `EntityTeleport` (>8 m deltas) is an ordinary discontinuity, not a violation |
| admin / mod-origin | exemption and cause-API paths, including calling-mod identity on the evidence record |
| rollback | disconnect at every step, save epochs, crash truncation, reconciliation without accusation |
| induced finding | a second player racing a victim's container, knockback/explosion impulses against a victim; the victim must accrue nothing |
| review-surface | evidence injection, tamper, truncation, and purge/redaction tombstones preserving the hash chain |

Mutation tests perturb a single field of a legal trace and assert the expected finding appears
(or that the trace stays legal). Mutations cover every validator input, including authority
class: any validator with a client-declared input is exercised in observe-only and never
asserts correction.

Exit: every planned detector has its full fixture set; replay is bit-reproducible for a fixed
seed; the mutation suite is green.

### 5. Integration tests

Dedicated server with stock vanilla clients and `7dtd-loadgen` drivers. Begin in observe mode,
then enable one corrective invariant per run and assert the exact transitions corrected
(identity and count) with no legal-context false corrections. Every Hard invariant executes
its legal-context matrix (spawn, death, teleport, buffs, knockback, explosion, high latency,
admin, other mods). A dedicated compatibility run exercises co-patching per the architecture's
hook policy: each reject seam with the supported mods active, exercising rejects, not just
coexistence.

Exit: zero false corrections in the legal matrix; rejects coexist with the mod stack.

### 6. Performance A/B

Paired runs with `7dtd-apm` on the same world, seed, bot count, duration, collectors, and
config, with and without Server Guard, after a warmup period and across at least three seeds.
Measured during a 64-client bloodmoon damage burst, per the architecture budget: under 0.5 ms
p95 added main-thread time per tick, under 1 percent worker CPU, bounded queues, zero
steady-state allocations in movement sampling, no unbounded evidence queue, and no increased
disconnect rate versus baseline. The two cost dominators (swept no-clip voxel queries and
full-inventory diffing) are reported from their per-detector counters, with drop counters when
queues shed soft observations. Report p50/p95/p99 and memory.

Exit: the full overhead budget holds, with confidence intervals on the reported percentiles.

### 7. Human soak and review

Long-run soak on the operator's live server; findings are labeled confirmed, benign, uncertain,
or detector bug (the policy's appeal dispositions). The movement detector family is not
considered for correction before at least 100 labeled player-hours. Labeled false positives and
detector bugs are exported to the regression corpus and replayed by the layer 4 harness, so a
fix ships with a failing-then-passing trace.

Exit: the labeling protocol runs for the full calibration window and feeds the release gates.

## Adversarial scenarios

Organized by domain; each scenario maps to at least one detector fixture:

- Protocol: malformed values (invalid enum, NaN, infinity, coordinate, stack size, length),
  unauthorized entity IDs, replayed requests, stage violations, floods (per-connection and
  global cost classes), join churn, duplicate sessions with reconnect grace.
- Movement: at, below, and just above each contextual envelope; burst loss and 500 ms jitter;
  legal jump, fall, ladder, swimming, crouch, encumbrance, buffs, knockback, explosion,
  teleport, spawn, death, vehicle collision, passenger motion, and server hitch; jetpack,
  parachute, elevator, helicopter flight, and rubber-band `EntityTeleport` after a chunk stall.
- Combat: fire/reload boundary timing for every action family; melee reach at moving targets;
  armor, buffs, difficulty, headshots, explosive and damage-over-time paths; both damage paths.
- Inventory and economy: concurrent container moves, split/merge, drop/pickup, death backpack,
  craft cancellation, workstation completion, trader transactions, disconnect during transfer,
  save rollback; locked containers, claims, allies, parties, wire tools, turrets, drones,
  vehicles, repair, upgrade, falling blocks, explosions, quests, and admin grants.
- World and entity: block, claim, reach, tool, material, cadence, and world-bound violations;
  wire endpoints; entity-spawn authorization; client-pushed progression
  (`NetPackageEntityAddExpServer`, `NetPackageEntitySetSkillLevelServer`) bounds; high-fan-out
  requests.
- Induced findings (anti-cheat weaponization): a second player racing the victim's container,
  repeated explosion knockback on a victim, duplicate-session games; the victim must accrue
  nothing.
- Availability: floods, join churn, expensive package spam; the throttle action never counts
  toward any enforcement gate.
- Review surface: dashboard authentication bypass or session theft, webhook alert spoofing,
  evidence injection into the JSONL chain, purge/redaction tombstones, crash truncation.
- Compatibility: each supported server-side mod individually and in the production set, with
  rejects exercised per seam.

## Test environment and reproducibility

- One pinned server build (V3.1.0 b14); every recorded trace carries the hook-manifest hash of
  the build that produced it.
- Synthetic traces, loadgen scenarios, and property tests use fixed seeds and an injected
  clock; replay results are bit-reproducible.
- Performance A/B uses identical world, seed, bots, duration, collectors, and config on the
  same host class; reports record the hardware and server config.
- CI runs layers 1-4 on every change. Layers 5-7 run on the operator's server per release
  candidate and during Phase 10 calibration.

## Release gates

The gates below restate [POLICY.md](POLICY.md) and the [architecture budget](ARCHITECTURE.md);
those documents are canonical if they ever diverge.

- Observe mode cannot alter gameplay under any detector failure; fail-open covers both startup
  resolution mismatch and runtime hook faults.
- Correct mode has zero known false corrections in the full legal scenario matrix, and every
  Hard invariant ships legal-context tests with complete authoritative inputs.
- No automatic permanent ban path exists.
- Every kick requires at least two independent strong categories or an operator-approved policy
  for a repeated hard protocol invariant.
- False-positive rate is reported with confidence intervals and separated by detector/context.
- At 64 loadgen clients: less than 0.5 ms p95 added main-thread tick cost (measured in the
  bloodmoon burst), bounded memory, no unbounded evidence queue, and no increased disconnect
  rate versus baseline.
- Evidence survives crash truncation, verifies its hash chain (including after purge/redaction
  tombstones), rotates, redacts, and expires.
- Installation, uninstall, observe-only rollback, and game-version mismatch are tested.
- Fixture coverage: every planned detector has normal and violation fixtures, and the mutation
  suite covers each validator input.
- No enforcement family is enabled without explicit operator opt-in after its dry-run diff
  review.
